# Contributing

## Workflow

1. Read `PROJECT_SPEC.md` before changing architecture or implementation.
2. Work within the active project phase.
3. Keep changes scoped and use Conventional Commits.
4. Run lint, type checking, formatting checks, and a production build before requesting review.

## Commit format

Use Conventional Commits, such as `feat: add portfolio content model`, `fix: handle invalid site URL`, or `docs: clarify deployment steps`.

## Pull request expectations

Describe the problem, the solution, verification performed, and any follow-up work. Do not mix unrelated refactors with feature work.
